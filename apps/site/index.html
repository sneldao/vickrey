A field journal that seals what you saw

A record can change.
The seal shouldn't.

Vickrey pairs a field observer's notes with an open-weight model that suggests — and an observer who decides. The decision is sealed on the device with a signature and a hash chain, so any later edit cracks the seal instead of silently rewriting the past.

How it works

  1. 01

    Observe & decide

    A photo, a suggestion from an open-weight model, and a human who confirms or corrects it. The observer — not the model — signs.

  2. 02

    Seal on the device

    The decision is hashed, Ed25519-signed, and chained to the record before it. The sealed journal is the source of truth.

  3. 03

    Compare later

    Sync anchors a commitment — never the raw photo — to a ledger. Edit a queued record and the hashes stop recomputing: sync refuses to send it.

  4. 04

    Context, outside the seal

    A web lookup adds what else is being reported nearby. It is shown beside the record, never inside it: a third party's answer cannot be part of a commitment someone must reproduce.

What is true today

Live and verifiable

  • The whole loop, from a cold browser: seal, tamper, sync refused, restore, three Anchored · VERIFIED.
  • Ed25519 device key and a hash chain, verified in the browser — every hash recomputes, every signature checks.
  • A correction is sealed beside the model's original suggestion, so neither can quietly overrule the other afterwards.
  • Real server-hosted Gemma 3 4B identification through the client (over a private tunnel — not on-device).

Live, with a stated limit

  • The block store runs in the ledger's own process. The application copy is still a separate store, so an edited copy still yields PAYLOAD_MISMATCH — but the block is not held by a separate process, so this is not an independent source.
  • The ledger says so itself: / reports independent_source: false. A test fails the build if that stops being true.
  • Point HORNET_URL at a real node and it reports true. That path is unrun.

Not yet

  • On-phone / offline model inference. Every model run so far was server-hosted.
  • Actual outdoor field use. The plates in the client are illustrations, not photographs.
  • Darwin Core export, so researchers can consume the records.
  • Atlas Vector Search: the Commons panel works, but per-record similarity needs a Search index that only the Atlas control plane can create.

Integrity is not accuracy. A seal proves a record was not edited after it was signed. It does not prove the identification was right — that is the model's job, and the two are kept visibly separate.

Why records like this matter

Open biodiversity data is enormous: GBIF reports >3 billion species occurrence records published by ~2,300 institutions (GBIF, 2025). That is ecosystem context, not Vickrey usage — and nothing here claims those records lack provenance. It is the scale that makes tamper-evident field records worth having.
